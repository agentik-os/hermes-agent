# Capability Gaps

## P0 Foundation

1. Universal AGK object identity, scope, relationships and compare-and-set writes.
2. Organization tenancy and membership.
3. Outcome-oriented Project with continuity independent of Runtime.
4. Agent Definition and Instance above `AIAgent`.
5. OS Definition, OS Installation, bindings and dependency graph.
6. Oracle mandate, state, inbox, decisions, KPIs and authority.
7. First-class Knowledge and Artifact domains.
8. Versioned runtime adapter contract and capability negotiation.
9. Normalized event envelope plus durable semantic ledger.
10. AGK authorization, Context Firewall and whole-process isolation contract.

## P1 Core product

- Team and Workforce Definitions, Instances and deployment snapshots
- recursive semantic Canvas and graph diff
- Design, Live and Inspect projections
- Stax or compatible layout and inspector behavior
- package manifest, provenance and immutable snapshots
- Eval and Verification orchestration
- Architect planning and semantic command foundation
- cross-runtime supervision and recovery

## P4 Future

- broad multi-runtime marketplace

## Hermes limitations that drive gaps

- single-tenant personal-agent trust model in `SECURITY.md`
- profiles isolate state but are not Organization tenancy
- in-process plugins are not a security boundary
- Hermes Project semantics conflict with AGK Project
- memory is not a governed Knowledge graph
- hooks are fragmented runtime events, not an AGK event ledger
- subagent lifecycle is process-local and non-reconnectable after restart
- desktop is branded and structured as Hermes chat first
- scheduler and kanban own their own stores, creating dual-truth risk
- several central modules are very large, increasing direct-patch conflict risk
