# AGK Vision

## Category and outcome

AGK is the Agentic Organization Operating System. Its customer outcome is to build and run AI-native organizations around outcomes.

AGK is project-first, outcome-first and organization-first. It is not a prompt library, Flow builder, coding assistant or agent launcher with additional dashboards.

## Product thesis

Hermes already solves a large part of agent execution. AGK adds the smallest coherent layer that Hermes does not attempt to own:

- tenant and Organization semantics
- outcome-oriented Projects
- persistent domain ownership through Oracles
- reusable domain intelligence through OS Definitions
- project-specific operation through OS Installations
- Team and Workforce semantics
- one canonical object and relationship graph
- governance, permissions, risk, policy and approvals
- knowledge, memory and artifact boundaries
- product-facing control plane and visual organization editing
- package, provenance and future marketplace semantics

Hermes remains a runtime foundation. AGK remains the product identity and control plane.

## One platform, five bounded universes

| Universe | Outcome | Complexity posture |
|---|---|---|
| Collective | Connect people through Community, spaces, groups, events, live collaboration and reputation | Social and relational |
| Learn | Develop human capability through education, practice, Labs and certification | Guided and calm |
| Build | Create and operate intelligent organizations through Operate, Design, Code and Inspect | Deepest technical universe |
| Deals | Turn capability and systems into business through opportunities, delivery and transparent attribution | Economic action first |
| Evolve | Improve the operator through private Self data and Personal OS projections | Restrictive and clear |

The universes share identity, Organization membership, permissions, search, inbox, notifications, object references, capability graph, artifacts, packages, events and design primitives. They do not import one another's internal UI or storage.

## Strategic loop

```text
LEARN / DISCOVER -> BUILD -> PROVE -> APPLY -> CAPTURE LEARNING -> IMPROVE
```

`APPLY` may mean internal use, client delivery, Package publication or capability demonstration. Deals can receive an applied, proven capability but is not required to close the smallest loop. Evolve improves the Human operator through the private Self domain in parallel and never becomes a mandatory stage inside every Project.

## Experience principles

1. Begin with the desired outcome, not an asset picker.
2. Show simple operational truth first and permit deep inspection.
3. Keep Chat, Canvas, API, CLI and code as projections over the same objects.
4. Preserve context when switching views and universes.
5. Never hide operational reality behind a friendly abstraction.
6. Make every consequential action explainable and auditable.
7. Separate reusable Definitions, scoped Installations or Instances, and Runs.
8. Keep Self data private beneath Evolve unless the user authorizes a specific crossing.
9. Prefer deterministic execution for deterministic work and models for cognition.
10. Reuse Hermes before extending, wrapping or replacing it.

## Priority

The current transformation builds architecture and evidence only. Foundational priority is the AGK domain model, runtime boundary, Project, Agent, OS, Oracle, Knowledge, Artifact, Events and permissions foundations. Product implementation remains blocked until architecture validation and affirmative operator authorization.
