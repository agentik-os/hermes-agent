# AGK Oracle Model

## Definition

An Oracle is the persistent owner of one domain inside a Project. It persists responsibility, not merely process uptime.

An Oracle is not:

- a long-running chat
- a manager Agent with a title
- an OS Definition
- an unbounded autonomous loop
- an Organization-wide owner of several Projects

## Required state

An Oracle requires:

- stable identity and Project scope
- mandate and authority boundary
- domain state projection and cursor
- decision history
- inbox and event subscriptions
- objectives, risks, KPIs and backlog
- escalation policy
- OS Installation bindings
- Team and Agent relationships
- Memory and Knowledge scopes
- evaluation and audit policy

Without these, it is a Manager Agent rather than an Oracle.

## Default sizing

The default is one Executive or Project Oracle. Domain Oracles are introduced only when a domain has independent persistent state, mandate, decisions, workload, policies, KPIs and escalation authority.

An Oracle never directly owns more than one Project. Organization-level reuse uses Definitions or an explicitly bound Organization Oracle Service with filtered projections.

## OS relationship

```text
Oracle persists responsibility
OS persists reusable operational intelligence
OS Installation binds that intelligence to the Project
Agents perform the work
```

An Oracle may use several OS Installations. It resolves policy and constraints by law level, scope, specificity and strength, never load order. Incompatible doctrine creates a conflict object rather than an arbitrary choice.

## Execution

The Oracle creates or coordinates finite Missions, delegates Tasks, requests approval, evaluates health and handles escalation. Continuous responsibility is implemented through event subscriptions, Automations and bounded Loop Deployments that create finite Mission cycles.

## Hermes mapping

Hermes has no Oracle primitive. A Hermes Agent process can execute Oracle work, but Oracle identity, state, inbox, subscriptions, authority and decision history remain AGK control-plane objects. Process persistence never substitutes for ownership semantics.

## Surface

Oracle Chat is a projection over the Oracle's scoped context and authority. The inspector shows mandate, current objectives, decisions, risks, KPIs, OS bindings, Teams, Agents, events and pending escalations. Live status is never inferred solely from whether a Hermes process exists.
