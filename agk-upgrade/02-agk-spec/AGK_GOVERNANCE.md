# AGK Governance

## Law stack

```text
L0 Laws
L1 Organization Constitution
L2 Project Constitution
L3 executable Policies
L4 OS Rules
L5 Oracle Contract
L6 Agent Contract
L7 Mission constraints
L8 Task instructions
```

A lower level can narrow and cannot weaken a higher restriction. Critical governance is compiled into executable policy rather than left as prose for a model to interpret.

## Foundational rules

- no critical actor is the only verifier of its own critical output
- no Agent increases its own permissions
- production executes immutable deployed Definitions
- consequential execution produces provenance
- autonomous Loops are bounded
- cross-Organization access is denied unless explicitly authorized
- Lab intelligence cannot silently become production doctrine
- Mission and Project identity survive lower-level runtime identity loss

## Decisions and conflicts

Compatible constraints compose. Incompatible constraints create a governed conflict object with sources, scope, affected work and available resolutions. Load order never decides doctrine.

## Emergency control

Emergency actions can stop execution, external effects or deployments. They never suspend law or grant authority.

## Hermes mapping

Hermes hooks, middleware, approvals and toolsets provide enforcement and observation seams. They do not define AGK governance. The control plane makes the decision and the Runtime supplies evidence that it enforced it.
