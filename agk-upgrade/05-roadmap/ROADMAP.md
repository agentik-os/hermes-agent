# AGK on Hermes Roadmap

## Sequencing decision

The original sequence placed implementation of the Hermes adapter before the AGK Project and governance foundations. That order is unsafe. The adapter contract comes early, but executable integration follows identity, object, permission, event and provenance foundations so the first Hermes call is governed and attributable.

## Phase 0. Evidence and reconciliation

- complete Hermes source audit
- freeze AGK ontology and semantic mappings
- complete Master Blueprint and post-Stepper alignment
- validate architecture and preserve closed implementation gate

## Phase 1. P0 shared contracts

- universal object and relationship contracts
- identity, Organization and membership contracts
- Permission, Risk, Policy, Environment and Approval decision
- Event envelope, schema registry and provenance
- Artifact, Knowledge, Memory and Context Manifest boundaries
- transactional outbox and Package trust roots

## Phase 2. P0 control-plane spine

- canonical object write and query API
- compare-and-set revision and typed relationship commands
- durable semantic event ledger
- search and projection freshness
- outcome-oriented Project and Agent Definition or Instance
- Mission, Plan, Task and canonical Run state
- canonical Session, lease, effect intent and recovery commands
- package and Adapter registries

## Phase 3. P0 Runtime contract and security boundary

- provider-neutral AgentRuntime Protobuf contract
- profile and whole-process sandbox lifecycle
- signed immutable Hermes Runtime bundle
- external supervisor and authenticated guest host
- fail-closed effect, authorization, secret and inference brokers
- Context Manifest verifier and Runtime event journal

## Phase 4. P0 executable Hermes integration

- `HermesRuntimeAdapter` only after every Phase 3 boundary passes
- model route and Budget adapter
- Tool, Skill and MCP mapping
- Context and Memory adapters
- normalized Run and Span events
- crash, checkpoint and recovery behavior
- Project Overview and entity-scoped Chat

## Phase 5. P0 OS and Oracle

- OS Definition and OS Installation
- OS dependency resolution and package manifest
- autonomy and authority axes
- Oracle mandate and domain state
- OS Canvas and Setup completeness

## Phase 6. P1 Team and Workforce

- Team membership and routing
- Workforce Definition, Instance and Deployment Snapshot
- communication contracts and bounded AgentCalls
- semantic organization Canvas

## Phase 7. P1 quality, package and deployment

- Eval and Verification foundations
- package provenance, snapshot and compatibility
- canonical Automation and Trigger adapter with reconciliation
- simulation and upgrade diff
- deployment reconciliation and rollback

## Phase 8. P1 AGK Web and Tauri shell

- canonical AGK Web identity and Tauri wrapper
- Learn, Build, Deals and Self surface switcher
- contextual sidebar and inspector
- Operate, Build and Inspect layouts
- recursive Canvas with Design, Live and Inspect
- Runtime drawer and deep links
- bounded Expo mobile observe and decide projection follows after the shared shell contracts

## Phase 9. P1 Architect foundation

Architect works only after object schemas and semantic commands exist. It proposes diffs, resolves dependencies, requests permissions, validates and applies approved changes.

## Phase 10. P2 bounded product foundations

- Learn objects and Open in Build bridge
- community spaces and explicit Opportunity creation
- Deals Opportunity to Deal to Engagement to Contract to Project bridge
- Self private objects and explicit cross-surface grants
- shared Inbox, notifications, search and entitlements

## Phase 11. P3 ecosystem

Marketplace publication, certification, capability graph, Portfolio provenance, referrals, Deal matching and creator Organizations.

## Phase 12. P4 future

Advanced Labs, automated optimization, regulated payments, complex commissions, large-scale reputation and alternative runtimes.

## Stop rules

A phase cannot begin because its documents exist. It begins only when predecessor contracts pass behavior validation and the operator opens the relevant implementation gate.
