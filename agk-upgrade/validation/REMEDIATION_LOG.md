# Adversarial Remediation Log

This log records material findings from the first independent review of `agk-upgrade` and the architecture-level remediation applied before the fresh review. It does not authorize implementation.

## Hermes audit accuracy

- Corrected provider and Memory directory census methodology so only directories count.
- Added Managed Modal to concrete execution backends.
- Added Session export and import, Tool-result storage, checkpoint mechanics, cron attempts, Verification Evidence, kanban events and delivery obligations to the machine registry.
- Corrected stale source symbols in the audit and added class and function validation.
- Split existing-mechanics disposition from the complete AGK capability strategy.
- Reclassified governed provider routing, MCP, Browser and execution environments as ADAPT.

## Canonical AGK semantics

- Restored exactly sixteen OS parts.
- Restored OrganizationOSInstallation, ProjectOSBinding and OSBinding distinctions and authority-floor rules.
- Kept Automation as one deployment binding, with Job, Run and Policy owning execution mechanics.
- Replaced the proposed parallel execution-attempt object with canonical Run state. Every retry or execution replay receives a new Run id.
- Restored the canonical Project stage machine.
- Kept Hermes Project as private adapter data and mapped imported folders only through RepositoryBinding.
- Restored Agent as the canonical persistent or ephemeral machine actor and Worker as a role. An AgentCall Span records a child Agent invocation without replacing child identity.
- Restored the canonical strategic loop and Deals chain.
- Kept Community under Learn and Project ownership under Build.
- Restored AGK Web, Tauri and Expo client boundaries. Hermes Electron remains a Runtime console and behavior reference.
- Made Stax, Context Stack, Inspector and LayoutDefinition distinct.
- Mapped Organization Canvas overlays to the seven canonical Flow Canvas modes rather than replacing them.

## Runtime and security

- Added the canonical Mission, Plan, Task and Run prerequisite.
- Expanded AgentRuntime to cover every declared operation, authenticated host and guest framing, cancellation, reconnect, event acknowledgment and effect reconciliation.
- Required signed immutable guest bundles before execution.
- Added sandbox-external supervisor, effect and authorization broker, model broker, strict Context Firewall adapter and Runtime event journal.
- Bound consequential calls to exact argument hashes and canonical Approval or ApprovalGrant references where required.
- Added transactional control-plane outbox and Runtime sequence, ACK, replay and gap contracts.
- Moved every governed workload behind whole-process isolation with no local fallback.
- Added a generic Hermes remediation task for nested Tool intersection, process ownership, per-MCP secrets, remote sync and A2A egress. Capabilities remain disabled until remediated.
- Moved Package signatures and trust roots to P0.
- Deferred scheduler reuse pending single-authority proof and operator ratification.
- Moved executable Hermes integration after all domain and security prerequisites.

## Validator hardening

- Writes a fail-closed in-progress result before validation and replaces stale PASS output on every exception.
- Rejects missing, empty and padded required artifacts.
- Rejects duplicate JSON and YAML keys and malformed consumed types.
- Validates exact source pins, canonical-source hashes, evidence manifest hash and relative paths.
- Validates mapping keys, capability files, classes and functions, inventory shape and evidence uniqueness.
- Validates canonical OS, Project, Run, strategic loop, Deals, client, Canvas and vocabulary contracts.
- Validates unique contiguous task ids, safe paths, document sections, exact dependencies, DAG and security ordering.
- Validates roadmap DAG, decision ids and statuses, master report sections and test evidence.
- Rejects arbitrary product code in the SSOT and detects working-tree, committed, rename and assume-unchanged changes outside it.
- Mutation suite expanded to 31 adversarial cases.

## Remaining authority

The canonical AGK Stepper is unchanged. The Build Gate remains CLOSED and admits no Step. Fresh independent semantic, runtime, audit and validator reviews all returned PASS for this planning snapshot. Their result does not ratify or implement the canonical Stepper.
